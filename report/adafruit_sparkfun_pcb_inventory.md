# Adafruit and SparkFun PCB definition inventory

The authenticated GitHub tree inventory found 1,556 repositories in the Adafruit and SparkFun organisations containing at least one `.brd` or `.kicad_pcb` source. Repositories were ordered by repository creation time so the definition work can proceed from the oldest designs forward.

## First chronological batch added

The following repository definitions were added to the organisation working files in the first two chronological passes:

- Adafruit: `monochron`, `TV-B-Gone-kit`, `Data-Logger-shield`, `Ice-Tube-Clock`, `Adafruit_Conway-Game-of-Life-Kit`, `DS1307-breakout-board`, `Adafruit-MAX6675-Breakout-Board-PCB`, `MicroSD-breakout-board`, `Adafruit_Brain-Machine-Kit`, `Adafruit_FTDI-Friend-PCB`, `Adafruit_Microtouch`, `Adafruit_USB_Boarduino_PCB`, `Adafruit-I2C-SPI-LCD-Backpack-PCB`, `Adafruit_Atmega32u4_Breakout_Board`, and `Adafruit-Proto-Screwshield-PCB`.
- SparkFun: `ADXL345_Eval`, `OpenLog`, `Serial_Alphanumeric_Display_Driver`, `Serial7SegmentDisplay`, `WiFly-Shield`, and `Simon-Says`.
- The next pass also added Adafruit's `Adafruit_1.8_Inch_TFT_Breakout_PCB`, `Adafruit_2.8_Inch_TFT_Shield_PCB`, `Adafruit_iCufflinks`, `USB-DC-Solar-Lithium-Ion-Polymer-charger`, `Adafruit-128x64-Monochrome-OLED-PCB`, `Adafruit_MCP73833_PCB`, and `TSL2561-breakout-board-PCB`, plus SparkFun's `ColorLCDShield`.
- The following chronological slice added Adafruit's `Adafruit_Motor-Shield-v1`, `Adafruit-VCNL40X0-PCB`, `2-axis-joystick-breakout-board-with-mounting-holes`, `Adafruit-RGB-LCD-shield-PCB`, and `Adafruit-Menta-PCB`.

Each source board is represented as its own version entry, including the separate revision files present in the older Adafruit repositories. Production panel boards were not included in this batch when a source board was present.

## Next chronological point

The next unadded source in the ordered inventory is Adafruit's `Adafruit-96x64-RGB-OLED-Breakout-PCB`, created 2012-03-08, followed by the remaining 2012 SparkFun and Adafruit boards. The remaining inventory should continue from that point without changing the existing declarations for projects already present.
